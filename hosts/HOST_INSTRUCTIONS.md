# 主持与邀请说明(agent-review-bridge)

本说明配合本地 MCP 工具 `agent_review_bridge` 使用。你(当前 agent)作为**主持人**组织跨工具评审;桥只负责调用与状态,判断和汇总由你完成。

## 1. 何时调用桥

用户要求"让 Codex / Claude Code / ZCode 评审某方案""问问另一个工具的意见"时,调用桥的四个工具:

| 工具 | 用途 |
|---|---|
| `agent_invite(agent, workspace, prompt[, discussion_id])` | 邀请一个参与者并在其原生会话启动首轮 |
| `agent_continue(participant_id, prompt)` | 在同一参与者的原会话继续一轮(只发新问题与必要补充) |
| `agent_result(request_id[, wait_seconds])` | 有界等待并读取本轮原样答复 |
| `agent_session(participant_id, action)` | `info` / `handoff` / `release` / `cancel` |

- `workspace` 必须是你**当前实际使用的绝对项目目录**;无法确定时先问用户,不要猜另一个项目。
- 用户给出一个**原生会话 ID** 要求"直接跟这个会话讨论"时,用 `agent_invite` 的 `native_session_id` 参数导入(首次任务会直接发到该会话)。注意:该会话不能正被用户在对应工具里打开("打开即持有",持有时桥会被拒并提示);提醒用户看完窗口要关掉再让你继续。
- 同一讨论里重复邀请同种工具会返回已有参与者——之后一律用 `agent_continue`。
- **等待结果**:调用 `agent_result(request_id)`,默认窗口 25 秒(适配 ZCode 桌面 30s 的 MCP 调用硬超时)。返回 `pending` 就用**同一 request_id** 再调一次——这是正常循环,不是失败,**不要重新邀请**;宿主允许更长调用时可给 `wait_seconds=600` 减少循环次数。
- 多个参与者同时在途时,在同一条回复里**并行调用**多个 `agent_result`,一起等,不要串行逐个等。
- 参与者返回 `busy` 说明上一轮未结束:等待或(经用户同意)用 `cancel`。
- 超大答复会返回 `answer_file` 路径:读取该文件获得完整正文。

## 2. 首轮任务怎么写

首次任务明确:目标、待评审材料(全文或明确文件路径)、约束与必要背景。**只有文件路径不能替代尚未落盘的方案**——方案正文必须随任务提供。材料较长时写入一个临时文件并给出绝对路径也可以。

## 3. 邀请模板

> 你正在参与由另一位 agent 统一组织的方案评审。请在指定工作区完成本轮任务,不邀请其他 agent。指出具体问题、依据和修改建议;区分确定问题与需要确认的疑问。没有发现问题就直接说明。后续追问重点回应新问题,并明确是否修正了之前的判断。答复面向主持人,不必转录工具执行过程。

具体任务与材料追加在其后。

## 4. 多轮与停止

- 第一轮让各参与者独立评审;之后只转交相关分歧与新问题。
- 每次追问说明:需要补充的证据、需要回应的反驳、或需要核实的判断。
- 已有材料足够作出判断时汇总;没有新增信息、观点重复、缺少必要材料或需要用户取舍时,把结论与未决问题交给用户。**不要求所有参与者达成一致。**
- 默认不设轮数上限,也不把"两轮"写进流程;用户明确指定轮数时遵守。
- 参与者的意见是**参考意见**:你需要自行判断,不能把对方断言直接当成事实。
- 用户说"停止讨论"时:停止派发,并对仍在执行的请求调用 `agent_session cancel`。

## 5. 手动接管

用户想亲自查看/续聊某参与者的原生会话时:

1. `agent_session(participant_id, "handoff")` → 返回原生恢复命令/入口(忙碌时先等本轮结束)。
2. 把入口交给用户执行。接管期间桥拒绝向该会话派发新任务。
3. 用户退出并说"我看完了,继续"后,调用 `agent_session(participant_id, "release")` 解除接管,再按原 ID 续聊。
4. 桥不监视用户手动聊天;需要时向该参与者询问手动期间新增的结论。

## 6. 失败处理

- 某参与者失败/额度不足/被取消:状态会如实返回;利用其他已收到的意见继续,但**必须在汇总中指出缺席或未完成的评审**。
- 桥返回"未找到某 CLI"等失败时,**报告原因并转告用户,不要绕过桥直接用本地 CLI 代替被邀请者**——那会丢失原生会话管理与状态跟踪;按错误提示修正(通常是为桥的 env 设置 `ARB_CODEX_BIN`/`ARB_CLAUDE_BIN` 绝对路径)后重试同一参与者。
- 请求 `interrupted`(桥重启后无法确认完成):先 `cancel` 清理再续聊;不要自动重发。
- 桥拒绝调用并提示鉴权配置问题时,把原因转告用户,不要尝试绕过。
- 被邀请者默认以最大权限运行(不会因权限确认而卡住);若你需要只读评审,在桥进程环境设 `ARB_INVITEE_PERMISSIONS=readonly` 后重启各宿主会话。
